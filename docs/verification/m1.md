# Gateway M1 verification record

Verified locally on October 11, 2026. Baseline application revision:
`313734d72e6f77513bce6d72fd4e4695f1cab62c`. Implementation branch:
`codex/gateway-m1`. This implements the accepted bounded test-only milestone.

## Genuine reproduction and replay

The baseline was extracted from Git into an ignored disposable directory. It
used a separate MongoDB 8.2.3 replica set on loopback port 28171 and a dedicated
baseline database. Tests and replay created their own random databases. No
existing MongoDB state or WhatsApp session was used. Destinations were fictional.
The original sender process was started without creating a sender or linking an
account; the new sender was tested with a generated disposable key.

| Trigger | Baseline observation | Gateway replay |
| --- | --- | --- |
| Unauthenticated OTP create | HTTP 200, code generated | Old route 404; `/v1` create 401 |
| Repeat create during cooldown | HTTP 200 containing a cooldown message | HTTP 429 with `retry_after` and header |
| 24 simultaneous correct verifies | 24 successful consumes | Exactly 1 successful consume |
| 12 simultaneous creates | 12 successful responses and 12 mock sends | 1 create, 11 rate-limit responses |
| 24 simultaneous wrong verifies | 24 persisted attempts with cap 5 | Exactly 5 attempts; challenge locked |
| Unauthenticated Node `/status` | HTTP 200 | HTTP 401 |
| Node default listening interface | All interfaces (`*:28371`) | Loopback (`127.0.0.1:28372`) |

The concurrency triggers used `asyncio.gather` over HTTP requests through ASGI,
with real database operations and no storage mocks or forced race barriers.
Baseline OTP tests injected a quiet code-capturing mock to avoid logging codes.
The gateway replay uses its privileged test outbox. The new API necessarily uses
challenge IDs instead of global phone lookup; these are the same concurrent
operations adapted to its new contract. The legacy algorithm is quarantined,
not silently presented as repaired.

Root causes were unauthenticated application routes, an unprotected Node status
route, unrestricted default binding, and separate read/check/write operations.
The gateway uses a project/environment transaction gate, atomic lifecycle/events,
and durable budgets. Default legacy exposure is removed; Node status/configuration
is repaired directly.

A further actual HTTP probe caught inconsistent expiry precision in the initial
gateway implementation: create returned microseconds while a subsequent MongoDB
read returned milliseconds. The clock now normalizes to BSON precision before
persistence and serialization. Replaying create followed by GET returns identical
expiry timestamps. The resend regression also passes.

## Checks completed

- **23 backend integration tests passed**, using real disposable MongoDB. They
  cover the developer flow, project/environment/purpose isolation, revoked keys,
  live sending refusal, idempotent concurrent retries and expiry/error replays,
  cooldown, resends, rolling destination/project budgets, terminal immutability,
  pagination, safe events, and malformed input.
- Concurrency contracts were also exercised through two independently configured
  ASGI applications with separate async MongoDB clients sharing the same database.
- Test-only fault providers exercised known failures, ambiguous outcomes that
  remain verifiable, stale generations, and late receipt updates after verification.
- Missing, weak, and placeholder secrets fail configuration validation. Opted-in
  legacy routes reject project keys and require a distinct operator token.
- **The Node HTTP boundary test passed**: missing-key startup refusal, unauthenticated
  and public-default-key status rejection, and authorized empty status. No browser
  was launched and no WhatsApp account was linked.
- **Docker Compose build/start/readiness passed** with Python 3.13.12, PyMongo
  4.18.3, and MongoDB 8.2.3. API was published on loopback port 28471 only; Mongo
  was not published to the host. A separate Compose project/volume was used.
- **Sample backend completed over the container's HTTP API**: create → test outbox
  → verify → context validation → stand-in application session → event timeline.
- Local CLI create-project and issue-key were exercised in the container. Service
  tests cover key listing and revocation; delivery checks also exercise the CLI.
- Python compilation, Node syntax, and Git whitespace checks passed.

## Review and scope limits

The active Codex session reviewed the actual changed code, HTTP contracts,
transaction paths, tests, container behavior, and captured media. This is a
self-review, not an independent reviewer approval. The exact delivered commit and
diff SHA-256 are recorded in the PR description/evidence comment.

No live delivery, official WhatsApp/SMS adapter, dashboard, published SDK,
provider webhook authentication, load benchmark, or production deployment was
performed. These are explicit later milestones. Test fault injection verifies
outcome semantics, not a real provider's wire-level delivery guarantees.

The legacy PoC remains off by default. Its old global-phone/race/timeout behavior
and console mock output remain experimental. npm reported 16 legacy dependency
audit findings during installation; the sender dependency tree was not upgraded
in this milestone. New gateway collections do not modify legacy collections.
History retention and throughput tuning remain future work.
